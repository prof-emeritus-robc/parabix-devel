# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Parabix is a framework for high-performance streaming text processing using SIMD and multicore parallelism. Programs are built as pipelines of kernels over *bit streams* (one bit per input code unit), and the kernels are JIT-compiled through LLVM at run time. Requirements: C++17, CMake ≥ 3.12, Boost ≥ 1.61, Z3, LLVM ≥ 16 (Release build).

## Build and test

Out-of-source builds live in sibling directories of the repo root (`build22/`, `debug-build/`, … several coexist; use the one you are working in).

```bash
mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release ..          # add -DCMAKE_PREFIX_PATH=/path/to/llvm for a custom LLVM
make -j8                                     # or: make -j8 <tool>   e.g. icgrep, tokenizer
make check                                   # builds everything, then runs ctest --output-on-failure
```

Binaries go to `<build>/bin`, kernel test binaries to `<build>/tests/bin`.

Running a subset:
- One ctest entry: `ctest -R <name> --output-on-failure` (names: `greptest`, `proptest`, `abc_test`, `u8u16_test`, `u32u8_test`, `nfd_test`, `nfc_test`, `editd_test`, `base64_test`, `gb18030_test`, `json_test`, `csv2json_test`, plus each kernel test in `tests/CMakeLists.txt`).
- The same suites also exist as make targets that skip the full build (`make greptest`, `make nfd_test`, …); they run the Python drivers in `QA/` against `<build>/bin/<tool>`.
- Kernel unit tests: `make kernel-tests` (all), or build and run one, e.g. `make test_scan && tests/bin/test_scan`. New kernel tests are registered with `parabix_add_kernel_test(<name> <module deps…>)` in `tests/CMakeLists.txt`.

## Code layout and architecture

`include/<area>` and `lib/<area>` mirror each other. Each `lib/` subdirectory is a CMake *module* declared with `parabix_add_module`; its target name is the path with dots (`lib/kernel/streamutils` → `kernel.streamutils`, `lib/re/cc` → `re.cc`). Tools in `tools/<name>/CMakeLists.txt` use `parabix_add_executable(NAME … SRC … DEPS <modules>)`, so a new dependency on a library area means adding its module name to `DEPS`.

Layers, bottom up:
- **`idisa`**: the IDISA builder, a portable SIMD instruction-set abstraction (`simd_*`, `hsimd_*`, `esimd_*`, `mvmd_*` operations at arbitrary field widths) over LLVM IRBuilder, with per-target (SSE/AVX2/AVX-512/ARM) implementations.
- **`kernel/core`, `kernel/pipeline`**: the kernel and pipeline framework. A kernel declares input/output `StreamSet` bindings (stream count × field width) with rate attributes (`FixedRate`, `PopcountOf`, `LookAhead(n)`, …). `ProgramBuilder`/`PipelineBuilder` wires kernels with `P.CreateStreamSet(n, width)` and `P.CreateKernelCall<K>(…)`. The pipeline compiler handles buffering, segment scheduling and multithreading.
- **`pablo`**: Pablo, a bitstream language whose programs are kernels (`PabloKernel::generatePabloMethod` builds an AST with `PabloBuilder`: `createAnd/Or/Not/Advance/Lookahead/MatchStar/ScanThru/If/While`, `Var` + `createAssign`). Pablo has its own optimization passes and a carry manager for Advance/addition carries across blocks. `pablo/bixnum` provides multi-bit integer arithmetic over parallel bit streams. `doc/pablo-syntax.md` covers the textual syntax.
- **`re`**: regular-expression AST, parsing, transforms, and compilation to Pablo; `re/cc` compiles character classes to bit-stream logic (`cc::Parabix_CC_Compiler`).
- **`ucd`**: Unicode Character Database tables, generated by scripts in `scripts/UCD/`.
- **`kernel/*`** (`basis`, `io`, `scan`, `streamutils`, `unicode`, …): reusable kernels. Examples: S2P/P2S transposition between bytes and bit streams; `FilterByMask` and deletion/spreading for compaction and expansion; scanning kernels that call back into C++ at marked positions.
- **`grep`, `csv`, `json`, `ldml`, …**: application libraries used by the tools in `tools/`. `icgrep` (`tools/icgrep`, `README-icgrep.md`) is the flagship.

### JIT compilation and the object cache

Kernels are compiled at run time, and the compiled objects are cached in `~/.parabix/objcache` (created by CMake). The cache key combines the **kernel name** with the linker build IDs of the running binaries. A kernel's name must therefore encode every parameter that shapes its generated body; otherwise, two configurations can be served each other's object code. Cache-related options are `-enable-object-cache`, `-trace-object-cache`, `-object-cache-dir=` and `-ForcePipelineRecompilation`.

### Toolchain options available in every tool (`lib/toolchain/toolchain.cpp`)

Useful for debugging generated code: `-EnableAsserts`, `-VerifyIR`, `-ShowIR[=file]`, `-ShowUnoptimizedIR`, `-ShowASM`, `-ToShow=<kernel name filter>`, `-PrintPipelineGraph`, `-SerializeThreads`, `-EnableCycleCounter`, `-TraceCounts`, `-time-kernels`, `-enable-illustrator`, `-thread-num=N`, `-segment-size=N`.
